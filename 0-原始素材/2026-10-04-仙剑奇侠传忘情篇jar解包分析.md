# 2026-10-04-仙剑奇侠传忘情篇jar解包分析

## 背景

桌面上躺着一个 `仙剑奇侠传-忘情篇.jar`（1.2MB），朋友发来的，问我认不认识这玩意。顺手就把它解了，结论挺有意思：**这是 2010 年 ETgame 做的功能机（Java ME）版仙剑，基本没加密，随便看**。把整个过程和复刻可行性沉淀成这篇。

## 第一眼

```
$ file 仙剑奇侠传-忘情篇.jar
Java archive data (JAR)

$ unzip -l 仙剑奇侠传-忘情篇.jar
354 个文件，共 1498489 字节
```

JAR 就是 ZIP，直接列目录。结构一眼看出是游戏：

```
ant/    75 个  动画（npc_1~41、fight_1~13、fight_skill、chengshi 城镇、guaiwu 怪物、chonglou 重楼、jiujianxian 酒剑仙）
map/    69 个  瓦片地图（cs_ljb_* 城镇、cs_ss_* 等）
bin/    18 个  图像（renwu 人物、portrait 头像、ui、chengshi、yewai 野外、fight_beijing 战斗背景）
mid/    10 个  MIDI 背景音乐（boss、menu、ss、xg、sz、yw）
str/    101 个 剧本/对话文本（.str）
cn/com/etgame/cls/system/   6 个类（包路径）
根目录   67 个 单字母混淆类（a.class ~ bo.class）
```

## 解包 + 确认身份

```
mkdir -p /tmp/xianjian && cd /tmp/xianjian
unzip -o -q /home/a1/仙剑奇侠传-忘情篇.jar
cat META-INF/MANIFEST.MF
```

MANIFEST 是实锤——这是一个 **J2ME MIDlet**（功能机游戏）：

```
MIDlet-Vendor: ETgame
MIDlet-Version: 1.0.0
MIDlet-1: 仙剑奇侠传,/icon.png,cn.com.etgame.cls.system.Startup
MicroEdition-Configuration: CLDC-1.0
MicroEdition-Profile: MIDP-2.0
```

入口类 `cn.com.etgame.cls.system.Startup`，javap 验证它 extends `javax.microedition.midlet.MIDlet`。

**猜身份有个弯路**：一开始看资源名（`chonglou` 重楼、`jiujianxian` 酒剑仙、`ss` 仙剑）想当然觉得是《仙剑一》。结果把 str 解出来才发现——紫萱、重楼、龙须叶、十里坡、余杭市集、苏州市集，全是《仙剑三》的素材，标题"忘情篇"是当年小厂借仙三素材/剧情挂个名的移植作。

## 文字乱码的弯路（重要）

解压后想直接看剧本：

```
$ head str/xuanze.str
�Z�o��...（一坨乱码）
```

第一反应是"加密了"。别急，先看文件头：

```
$ od -A x -t x1z -N 16 str/xuanze.str
1f 8b 08 00 00 00 00 00 00 00 ...
```

`1f 8b` 是 **gzip 魔数** —— 不是加密，就是压缩。教训：**看到二进制乱码先 od 看头，别急着下"加密"结论**。

然后 zcat 解压：

```
$ zcat str/xuanze.str | head -c 300
STR& script.openScriptList(); player.showFace(duihua);
dialogBox.showPlayerPortrait(); dialogBox.setType(type_left);
dialogBox.setText(/重楼/：本座不找了。);
...
```

**解压后直接是明文 UTF-8 的自制脚本引擎语法**。还犯了个小错：先按 GBK 解（想着中文游戏该是 GBK），出的是 `鏀诲嚮`（UTF-8 被当 GBK 读的典型乱码），换 UTF-8 就全对了。

## 加密性评估

**结论：基本没加密，只是做了 ProGuard 级别的符号重命名。**

| 层 | 处理 | 验证方式 |
|---|---|---|
| class 字节码 | 无加壳/无字节码混淆，仅类名/字段名改成 `a`、`b`、`e`… | javap -p 直接读，类型签名全保留 |
| 字段类型 | 明文 | `javap -p e.class` → `private Image[] d; private Vector r; private Hashtable w;` |
| str 剧本 | 仅 gzip 压缩（魔数 1f 8b） | zcat 即明文 UTF-8 |
| mid/ant/map/bin | 未加密自定义二进制 | 结构可逆 |
| 数值表 | 明文 | 炎咒/冰咒/雷咒/飞岩术、止血草/金创药、攻击×114、重楼×77 |

全量统计：str 解压后 9 万字符、中文约 1.5 万字（差不多 3.7 本小说的量）；67 个类共 476KB 字节码，主类 `e.class` 59KB（javap 159 行）。

一句话：**2010 年功能机手游的水平，厂商只做了最低成本的名字混淆，逻辑、文本、数值、技能公式全裸奔。** 当年随便一个懂 Java ME 的人一个下午就能把剧情和数值全提出来。

## 复刻可行性（分层评估）

问"复刻难度高不高"得先拆清楚是哪一种，投入量从低到高：

| 层级 | 做法 | 投入 | 备注 |
|---|---|---|---|
| L0 | 解包抽资源（剧本/地图/动画/音乐/数值） | 1-2 小时 | 零门槛，本篇前半就是教程 |
| L1 | 反编译改名重新打包 | 1-2 天 | CFR/JD-GUI 一键还原 Java 源码，纯侵权，只能自娱 |
| L2 | 理解玩法 + 换现代平台重做 | 2-4 周（1 人全职） | 引擎用 RPG Maker/Godot/Canvas，资源转换后复用 |
| L3 | 完全原创（素材也自己做） | 1-3 个月 | 卡点不在代码，在美术（69 张地图 + 75 组动画） |

**技术难度：低（⭐⭐/5）** —— 这是 2010 年功能机复杂度，地图渲染（瓦片+精灵）、回合制战斗（五行仙术+气值+好感度）、剧本解释器（它自己的语法很土，自造 200 行够用）、存档任务都是标准 RPG 套路。

**内容难度：高（⭐⭐⭐⭐/5）** —— 瓶颈是美术和剧情，不是代码。真正复刻的难点从来是"有没有人愿意画 69 张地图"，不是"能不能写出来"。

性价比最高的练手路径（L2 走捷径版）：用 Phaser/Canvas 只复刻前 1/4 地图（渔村→十里坡→山神庙→苏州），战斗简化为"攻击+3 个仙术"，一周能出个能跑通一段剧情的版本。

## 坑与教训

1. **看到乱码先 od 看文件头**：`1f 8b` = gzip（压缩），不是加密。别看见二进制就慌。
2. **中文解码先试 UTF-8**：功能机游戏编码不一定是 GBK。UTF-8 被当 GBK 读会出现 `鏀诲嚮` 这类特征乱码，反过来一眼就能认出来。
3. **JAR = ZIP**：`unzip -l` / `unzip -o` 直接就能看/解，不需要 Java 环境。
4. **文件名猜身份会翻车**：重楼/酒剑仙让"仙剑一 vs 仙剑三"判断失误，文本解出来才是实锤。资源名只能当线索，别当结论。
5. **功能机游戏没你想的那么有防护**：2010 年手游生态粗糙，符号混淆就是天花板了，字节码类型签名全保留，CFR 一拖就是源码。
