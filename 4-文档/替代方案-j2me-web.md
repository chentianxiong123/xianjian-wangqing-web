字节，j2me-web 是"直接执行"而不是"重新实现"。

## 二、j2me-web 是什么

**https://github.com/chentianxiong123/j2me-web**

用 TypeScript 从零写的 J2ME 运行时：内置一个小 JVM 直接解释 MIDlet 字节码，
并把 CLDC / MIDP 的 API 实现到 canvas、WebAudio 和浏览器存储之上。

- 纯前端，无后端、无 Docker、无真 JVM、无 WASM、无 CDN
- 产物 4 个文件，tar.gz 约 53 KB
- 打开页面 → 选 `.jar` → 直接玩；文件不上传，存档只在自己浏览器里
- 本仓库的《仙剑奇侠传-忘情篇》已实测可玩（打包成单页直开也验证过）

一句话对比：复刻是"把游戏重新写一遍"，j2me-web 是"把原版跑起来"。
前者的上限永远受限于逆向覆盖度，后者没有这个问题。

## 三、怎么部署（这才是本仓库现在缺的东西）

本仓库的引擎要靠 `python3 -m http.server` 在本地跑，没有公网部署路径。
j2me-web 的方法论是现成的，文档在它的 `docs/静态托管方法论.md`：

**https://github.com/chentianxiong123/j2me-web/blob/main/docs/静态托管方法论.md**

要点摘抄（细节看原文）：

1. **产物是纯静态**，没有后端，丢到 GitHub Pages / Cloudflare Pages /
   Nginx / 对象存储都能跑。`base: './'`，放子目录不会 404。
2. **`file://` 直接双击 `index.html` 也能跑** —— 因为没用
   `SharedArrayBuffer`，不需要跨源隔离，对 HTTPS 也没有硬性依赖。
3. **选型第一约束是"产物能不能进 git"**，不是速度也不是价格：
   - 不含游戏的模拟器本体 → git-based（GitHub Pages）没问题
   - **含《仙剑》jar 的构建 → 必须用 direct upload**，不能进仓库
4. **git 里没有删除，只有"不再引用"**：`git rm` + force push 救不回对象，
   历史、缓存、第三方镜像都可能还留着。用 git-based 传不该公开的东西不可逆。
5. **验证要分五层**：`curl` 返回 200 只证明文件存在。本仓库"测试全绿 ≠ 游戏能玩"
   的教训在这里同样适用 —— 逻辑层只能靠真实浏览器验证。

### 单游戏打包（打开即玩，连 jar 选择界面都没有）

j2me-web 里有一条实验线，把模拟器和指定 jar 编译进**同一个静态页面**：

```bash
npx vite build --config experiments/pack-jianxin/vite.pack.config.ts
```

《仙剑奇侠传-忘情篇》实测：3 个文件 1.72 MB，tar.gz 1.20 MB，
打开直接进游戏，不出现库界面，也不暴露 jar / J2ME 这些概念。

详见 `experiments/README.md`：
**https://github.com/chentianxiong123/j2me-web/tree/main/experiments**

**注意**：这个产物含商业游戏 jar，**只能用 direct upload 部署**
（Cloudflare Pages / Netlify 等的 CLI 或拖拽上传），不能走 GitHub Pages。

## 四、存档：别再自己造轮子

本仓库的引擎自己有存档。j2me-web 的存档是**自包含的单个 `.jsav` 文件**，
内含游戏 jar + 全部 RMS 记录库 + 偏好设置：

- 库顶部「备份全部」：所有游戏进度 + 所有 jar，一个文件
- 「恢复备份」：读回全部；文件里带了 jar 而库里没有的游戏会自动入库
- 游戏内 `⇅`：单游戏导出，可以把游戏连着进度一起发给朋友

跨设备、换浏览器、清缓存前备份一次就行 —— 不依赖任何账号或服务器。

## 五、本仓库剩下的价值（不是玩具）

**别把 73 类反编译、9976 个地图对象、1146 条脚本当成沉没成本。**
它们是**认识这个游戏怎么工作的唯一权威资料**，价值在于查证和复用：

| 资产 | 规模 | 用途 |
|---|---|---|
| 反编译源码 | 73 类 / 20273 行（CFR 0.152） | 查"这个怪癖为什么存在"、j2me-web 遇到反常行为时的对照物 |
| 地图 | 69 张 / 9976 对象 / 3526 碰撞盒 | 结构化数据，可直接复用 |
| 脚本指令集 | 101 STR / 1146 条 | 同上 |
| 格式规范 | ANT / MAP / BIN / STR / MID | 字节级格式全破，且有校验脚本锁死 |
| 截图 | 7 张 | 画面还原的参照 |

**j2me-web 和本仓库是互补关系，不是替代与被替代。**
j2me-web 负责"跑起来、给别人玩"，本仓库负责"解释清楚它内部是什么"。

## 六、如果还想继续这个项目

建议先把目标改成下面之一（**不要**再冲剧情覆盖率）：

1. **做 j2me-web 的兼容性补丁** —— 遇到某个游戏跑不对，用本仓库的反编译源码
   定位原因，在 j2me-web 里修。修的是运行时，一个补丁能让**所有**游戏受益。
2. **做数据导出工具** —— 把本仓库的地图/脚本/配置做成可查询格式，
   给玩家做攻略或图鉴，不需要重写游戏。
3. **做存档迁移器** —— 真机备份（`RMS` 导出格式）→ `.jsav`，或者反过来。
4. **就这样归档** —— 逆向成果当资料库用，`4-文档/` 里每个结论都带出处和测试锁，
   本身就有价值。

如果目标还是"做一个能玩的网页版"，**先停手**，
去 https://github.com/chentianxiong123/j2me-web 看一眼再决定要不要继续投入。
