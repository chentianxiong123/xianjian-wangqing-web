## 四、怎么复现这些结论（3 条命令）

```bash
cd /mnt/shared/仙剑奇侠传忘情篇-逆向工程
```

单图哑批次判定：某图 jar 文本 N 条，逐批门解完后引擎只吐出 M<N，且某些
`sig` 产出 0 句 → 该批次"门能开但不播"，是引擎 bug（对照数据即知：数据在、
门可满足、就是没执行）。

## 五、四个已修的引擎 bug（供接手者避坑，别再踩）

1. **地图级批次门控缺失**（元凶）：条件只写在 `openScriptList` 行、批内行不带条件，
   `Interp.runAll` 无跳批语义 → 每次进图把所有批全播 → 标记乱立、后批门永远打不开。
   修在 `xj_script.js:runAll`（与 `execAst` 对齐）。
2. **细线触发区/墙踩不到**：触发区多 3-12px 细线，16px 整格跳的点判定永远跨过。
   修：`World.segHits` / `solidSeg` 线段判定。
3. **进图即战死锁**：地图 build 暂停与战前 H2 暂停互相覆盖 → 回车无反应。
   修：`stashedRunner` 暂存 + `endBattle` 恢复。
4. **悬空对话框**：exec 脚本 `setText` 后无 hide 批次时对话框永不消失，按确定键无反应。
   修：`interact()` 回车即关。

其中 2、3 是我自己引入的回归（原版数据没错），1 是原实现就缺，4 是今天新发现。

## 六、诚实总结

- **能拿出手的**：逆向 + 数据 + 语义文档 + 验证工具链。这套东西能让任何人在几天内
  知道这个 jar 的一切，包括原版自己的死内容和 bug。
- **拿不出手的**：一个能玩的游戏。20.6% 的剧情覆盖率意味着玩家玩到的是"片段"，
  不是"故事"。**我不认为这算"复刻完成"。**
- **如果重来**：先建覆盖率度量（第一天就写 xj_ff.js），再动手写引擎。
  引擎最后写，度量先行——这次全栽在"没有度量，只有绿测"。
