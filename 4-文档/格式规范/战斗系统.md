## 0. 一句话结论

战斗是**行动条（速度条）驱动**的回合制：每个单位每帧按速度累加行动条，
到 **750**（= `1000 × 135 / 180`）时行动、到 **1000** 时执行技能；
伤害 = `技能公式(slv, 攻方攻 − 目标防) × 随机(9~11) / 10`，闪避率 = `目标运/100`，暴击率 = `施法者运/200`。

| 项 | 值 / 公式 | 出处 |
|---|---|---|
| 行动阈值 `W` | `1000 * 速度条的实际技能长度 / 速度条的实际可用长度` = `1000*135/180` = **750** | `ax.java:49` |
| 行动条上限 | 1000 | `ax.java:125` |
| 伤害浮动 | 均匀整数 `[9, 11]` → 0.9x ~ 1.1x | `ax.java:508` |
| 闪避率 | `目标运 / 100` | `ax.java:486` |
| 暴击率 | `施法者运 / 200` | `ax.java:535` |
| 变身减伤 | `dmg * 3 / 5` | `ax.java:521` |
| 变身气耗 | 每回合 `气 -= 10`（`d.U[7].j`） | `bd.java:45` |
| 等级上限 | 45（除非 debug flag 500） | `f.java:1076` |

## 2. 行动条（速度条）

```
W = 1000 * am.k / am.j                       // ax.java:49
  = 1000 * 速度条的实际技能长度 / 速度条的实际可用长度
  = 1000 * 135 / 180 = 750
```
两个长度都来自 `config_fight.str`。

### 每帧推进（`ax.java:119-161`）

```
① 仅当「敌人尚未全灭」且「本单位未定身」时推进：
     等待中： i += 速度(Q) + 速增(a)
     行动中： i += 技能速度(c) + 速增(a)

② 阈值吸附：若 W < i < W + (速度+速增) 且尚未行动 → i = W
     避免高速单位冲过 750 导致整场打不了

③ 硬上限：  i > 1000 → i = 1000

④ buff 递减：当 i ∈ [速度+速增, 2*(速度+速增)) 时，
     三组 buff 各递减一次剩余回合；剩余回合归零则数值清零

⑤ 回合开始： !已行动 && i == W  → c()，置 已行动 = true
⑥ 回合结束： 已行动 && i == 1000 → b()（执行技能）
```

`c()` = 玩家开指令菜单 / 怪物 AI 选技能；`b()` = 真正打出这一击。
`h()` 重置：`i=0, aa=0, 已行动=false, r=false`（`ax.java:238`）。

### 死亡与重伤

```
精 <= 0 且 处于 站立/消失 → 精置 0，播「死亡中」，状态置 7        // ax.java:213
精 < 最大精*2/10          → 精灵切「重伤」帧                      // ax.java:577
```

### 排序显示

`f.e` 按行动条速度做冒泡排序（降序）后绘制，**纯视觉，不影响出手顺序**（`f.java:551`）。

## 3. 伤害结算

主函数：`ax.java:494  a(String label, ax target, int type, int delay)`

```
0. 前置：目标非空 && 未死亡 && 目标精 > 0

1. 攻击优势 adv = (攻方.K + 武增C) − (目标.L + 防增E)

2. 分支：
   adv > 0  → 走技能公式
   adv <= 0 → dmg = 1（固定 1 点）

3. slv  = 技能等级(当前技能)
   base = 技能.伤害公式(slv, adv)          // af.java:76
   roll = 均匀整数[9, 11]
   dmg  = base * roll / 10                // 整数除法
   dmg  = max(dmg, 1)

4. 变身中(ac) → dmg = dmg * 3 / 5          // ax.java:521

5. type != 6(闪避) 且 0 < 目标行动条 < 750 → 目标行动条 -= delay

6. 按结算类型落地：
```

| type | 名称 | 规则 |
|---|---|---|
| 3 | 普通攻击 | 怪物用变身技时先给目标 `气 += 攻方R`；`rand(施法者运, 200)` 命中且 `dmg != 1` → `dmg *= 2`（暴击）；最后 `dmg = min(dmg, 目标当前精)`。若自身带反击标记 `B`，回精 `max(1, dmg/4)` |
| 5 | 格挡 | `dmg = (dmg >>= 1) <= 0 ? 1 : dmg`，再 `min(dmg, 目标精)` |
| 6 | 闪避 | **不扣血**，只弹「闪避」 |
| 1 | 单体 | 转 `ax.java:423` 走单目标判定 |

### 命中判定（`bd.java:160` / `g.java:143`）

```
玩家出手 → 遍历全部存活敌人，每人独立判定：
    若 目标.格挡中(ab) → type 5 格挡
    否则若 !已行动 && 目标精>0 && rand(目标运, 100) → type 6 闪避
    否则 → type 3 普通攻击

怪物出手 → 遍历全部存活玩家，顺序相反（先格挡后闪避）
```

> **重要**：普通攻击是**范围命中**，范围内每人各判一次闪避，不做单目标骰子。
> `bd.H()` 用 `j.a(...)` 圆判定（`j.java:123`：`dx²+dy² <= r²`）检查目标是否在攻击距离内。

### 飘字类型（`a.java`）

| type | 含义 |
|---|---|
| 0 | 普通伤害 |
| 1 | 暴击伤害 |
| 2 | 闪避 |
| 3 | 回精 |
| 4 | 未命中（目标不存在） |

### ★★ 已确认的原实现怪癖：怪物等级恒为 1

`g`（怪物战斗单位）构造器第 26 行是 `this.l(1)`，即 `ax.H = 1` 写死。
所以 `g.a(int)` 恒返回 `(1+20)/20 = 1`：

- **所有怪物的技能公式里 `slv` 恒为 1** —— `冰咒` 恒为 `atk/3`，`炎咒` 恒为 `atk`。
- 怪物的「仙术速度」`10+4*(slv-1)` 恒为 **10**。
- 真实等级只通过 `bm` 内部变量 **`lv`** 参与生命/速度/经验/金钱的表达式求值
  （`bm.java:139` 在解析前先 `q.a("lv="+n)`）。
- `bm.p()`（等级）只用于一行日志输出（`f.java:453`）。

**这是原版行为，不是解析错误，复刻时不得"修正"。**

## 5. 增益（buff）

施法者 `lv` = 对该技能的技能等级。

| 指令 | 效果 | 时长 | 出处 |
|---|---|---|---|
| `player.addatk` | 目标 `武增 = (10 + 5*(lv-1)) * 施法者.攻击 / 100` | `lv + 2` | `ax.java:1024` |
| `player.adddef` | 目标 `防增 = (10 + 5*(lv-1)) * 施法者.防御 / 100` | `lv + 2` | `ax.java:1033` |
| `player.addspeed` | 目标 `速增 = 1`（**固定值，与 lv 无关**） | `lv + 2` | `ax.java:1043` |
| `player.addAll` | 对全部存活队友同时施加上面三种 | `lv + 2` | `ax.java:1055` |

> **怪癖**：增益数值取的是**施法者**的攻击/防御，不是目标的。

### 过期

行动条每次进入 `[速度+速增, 2*(速度+速增))` 区间时，三组 buff 的剩余回合各 −1；
减到 0 时**数值清零且剩余回合归零**（`ax.java:127-152`）。

UI 图标判定：`A()` 武增生效、`B()` 防增生效、`C()` 速增生效
（均为 `剩余>0 && 数值>0`）。

## 9. 结算

### 胜负判定（`f.java:950`）

```
全部玩家死亡 → 状态 2（败）
全部敌人死亡 → 状态 1（胜）
```

### 胜利（`f.java:1020 f(1)`）

```
① 掉落：逐条 `item(百分比)`，rand(百分比, 100) 命中则掉落，最多 3 件
② gold = Σ 各怪物均匀金钱 ；exp = Σ 各怪物均匀经验
③ debug flag「四倍修行」打开时：exp <<= 2 且 gold <<= 2
④ 逐个队友：
     存活 → 好感度与精按战斗快照恢复；g(经验) 返回真则提示升级
     阵亡 → 好感度 -= 5，且精强制置 1（不死，代价是掉好感）
⑤ 等级上限 45，除非 debug flag 500
```

> 阵亡不扣经验，扣的是**好感度**，且精强制留 1 点 —— 这是游戏里客栈「复活」机制的来源。
